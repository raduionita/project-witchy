# Cycle Trust Roadmap

All phases ship under `CHANGES.md` Update 22 - 2026.10.22.

## P0 - Stop the app from lying [done]

Correctness and safety bugs that made predictions contradict what the user logged.

- [x] Late cycle becomes an explicit overdue state. Fertility surfaces pause and Today suggests a test instead of showing a fresh ovulation window.
- [x] Elapsed cycle day is separate from the projected modular day. A 39-day cycle reads "Cycle Day 39", not "Cycle Day 11".
- [x] Spotting-only spans no longer seed period starts, cycle lengths, bleed averages or BBT/OPK baselines.
- [x] A one-day gap inside a bleed is bridged, and observed cycle lengths below 15 are rejected.
- [x] One due-date basis: earliest = trimmed shortest, latest = trimmed longest. Late starts only after the latest date.
- [x] The predicted window stays anchored to the last period start and never rolls one bound into the next cycle.

## P1 - Make every screen tell the same story [done]

Consistency fixes so every surface reads from the same state and the same confidence rules.

- [x] Due-date countdown never flips to the next cycle while the current period is due or late.
- [x] Fertility gating is centralized; every surface checks the same confidence rule.
- [x] BBT/OPK confirmed ovulation can move the current cycle's fertile window and peak on Today, Fertility and Chart.
- [x] Spotting UI matches the math: period tags and the menstrual phase require period flow, not any flow.
- [x] Calendar shows the earliest-latest window in cycle mode when the history has a real spread, not only in perimenopause.
- [x] Calculator APIs guard themselves so direct callers cannot project past the stop threshold.

## P2 - Trust the data you already collect [pending]

Improve the quality of the inputs instead of adding new models.

- [ ] Use the median recent bleed length instead of a single average.
- [ ] Merge overlapping explicit period records.
- [ ] Use logged signals that are currently ignored.
- [ ] Harden BBT shift detection against fever and poor-sleep nights.
- [ ] Make the estimated-record policy explicit in the UI and the math.

## P3 - Model the bodies the app cannot represent [pending]

New modeling for cycles the current single-length, single-window model cannot describe.

- [ ] Variable fertile window length and position.
- [ ] Contraception and hormonal birth control mode.
- [ ] Missed-period test pathway with a negative-test state.
- [ ] Postpartum, breastfeeding, miscarriage and PCOS-aware tracking.
- [ ] Explicit clamp policy for very short and very long cycles.
- [ ] Historical snapshots so past predictions do not change retroactively.
- [ ] Trend detection for cycle length, bleed length and symptoms.

## P4 - Lock it down with tests [pending]

Protect the whole roadmap with regression and property coverage.

- [ ] Regression tests for every P0-P3 behavior.
- [ ] Property tests for cycle math across date, DST and leap-year boundaries.
- [ ] Full mode-matrix coverage across cycle, perimenopause, pregnancy and contraception states.
- [ ] Gates stay green: `flutter analyze`, `flutter test`, `flutter build apk --debug`.
